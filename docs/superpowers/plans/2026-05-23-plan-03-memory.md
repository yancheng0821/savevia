# savevia-ai Memory System — Implementation Plan (Phase 3)

> **Status:** SKELETON. Step-level detail to be written when Phase 3 begins, after Phase 2 (agent + chat) is merged.

**Goal:** Port Java's `MemoryExtractionService` (605 LOC) and `MemoryInjectionStrategy` (162 LOC) to Python LangChain chains. Memory extraction runs async after each chat response — analyzes the conversation, extracts durable user facts ("user has a TD Cash card", "user shops at Costco weekly"), and writes them back to the user service's `user_memory` table via HTTP. Memory injection (already wired up in Phase 2 as the LangGraph `state_modifier`) gets richer prompt formatting.

**Architecture:** Memory extraction is a **separate LangChain runnable** (not part of the main ReAct graph). Invoked from a background task (`asyncio.create_task`) at chat-response-complete. JWT for the writeback HTTP call is captured at request-start and passed into the background task closure.

**Tech Stack:** langchain-core, langchain-openai, plus Phase 1 + Phase 2.

**Reference spec:** `docs/superpowers/specs/2026-05-23-python-rewrite-design.md` §6 (Memory System)

**Estimated effort:** 6 person-days (1 week solo).

## Key Design Decisions to Confirm Before Writing Step-Level Detail

1. **JWT lifetime for background task**: user JWT typically expires in 24h. Background task runs in seconds, so no concern in practice, but document the constraint.
2. **Extraction failure handling**: if the writeback to Java fails, do we retry? Log and drop? Both have downsides — match Java's current behavior (likely log + drop).
3. **Deduplication**: Java's `MemoryService` likely deduplicates incoming facts vs existing. Confirm whether Python sends raw extractions and Java dedupes, or Python dedupes first.
4. **Structured output approach**: use OpenAI's JSON mode, function calling, or `langchain.output_parsers.PydanticOutputParser`? Pick based on Java's current method.
5. **Token budget**: extraction prompt + conversation can be long. Confirm Java's token limit and matching truncation strategy.

## Definition of Done

- Extraction runs after every chat turn (verified via integration test)
- Extracted facts match Java's output ≥80% on 20-conversation regression suite
- Writeback to Java user service succeeds; facts visible via `/api/v1/memory/users/{id}`
- Background task does not block SSE response
- Background task failures are logged but never crash the chat request
- All Phase 3 unit tests pass; Phase 1 + Phase 2 tests still pass
