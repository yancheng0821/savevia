## 4. Workstream A — Flinks / Bank-Connection port

### 4.1 Endpoints (8, exact parity)

All under `/api/v1/optimize/bank`, `X-User-Id` header, `Result<T>` envelope:

| Method | Path | Behavior |
|---|---|---|
| GET | `/flinks-config` | returns `{customerId, iframeUrl, sandbox, connectUrl, connectionLimit:{used,max,remaining,canConnect}}` |
| GET | `/connection-limit` | `{used, max, remaining, canConnect, yearMonth}` |
| POST | `/connect` | body `FlinksConnectRequest{loginId, institutionName, accountId?, userCardIds?}` → `BankConnectionDTO` |
| GET | `/connections` | `List<BankConnectionDTO>` for user |
| GET | `/connections/{id}` | one `BankConnectionDTO` (404-as-`Result.error("Connection not found")` if not owner) |
| POST | `/connections/{id}/refresh` | local-only status check, **no Flinks call, no `lastSyncAt` change** |
| POST | `/connections/{id}/resync` | limit-checked force refresh from Flinks; records a connection usage; body `{userCardIds?}` |
| DELETE | `/connections/{id}` | set status `DISCONNECTED`, record disconnect history (does **not** restore quota) |

### 4.2 Response DTO parity

`BankConnectionDTO`: `{id, institutionName, status, lastSyncAt, errorMessage, accounts[], createdAt}` where `lastSyncAt`/`createdAt` serialize as `yyyy-MM-dd'T'HH:mm:ss` (no zone, no millis — Pydantic field serializer). Nested `BankAccountDTO`: `{id, accountType, accountName, accountNumberMasked, balance, isActive}`. Field names camelCase via Pydantic alias; `response_model_by_alias=True`.

### 4.3 Module layout (worktree `savevia-ai/app/`)

```
repositories/
  bank_connection_repository.py     # findByUserId / findById / findByUserAndLoginId
                                    # / findByUserAndInstitution / insert / updateStatus
  bank_account_repository.py        # findByConnectionId / insert / update
  connection_limit_repository.py    # findByUserAndMonth / insert / updateConnectionCount / insertHistory
modules/
  connection_limits/service.py      # ConnectionLimitService parity (see 4.4)
  flinks/
    client.py                       # httpx wrapper: authorize + getAccountsDetail (real path, inert)
    demo_data.py                    # generateMockAccountsData + mock debit/credit txns (SEED-INJECTABLE)
    service.py                      # connect_bank / refresh / force_refresh / fetch / save accounts+txns
                                    # / match_credit_card_to_user_card / map_account_type / mask_account_number
  bank/
    router.py                       # the 8 endpoints
    schema.py                       # FlinksConnectRequest, BankConnectionDTO, BankAccountDTO
```

`flinks/service.py` reuses existing Python building blocks: `modules/transactions/categorization.py` (auto-categorize), `clients/card_client.py` (`get_cards_by_ids` for matching), `repositories/transaction_repository.py` (`find_by_account_and_flinks_id` dedup + insert). Wire `bank/router.py` into `app/main.py`.

### 4.4 Behavior parity details (must match Java exactly)

- **connect_bank**: dedup by `loginId` → if found, status `REFRESHING`, local refresh, `recordRefresh` (no quota). Else dedup by `institutionName` (demo-mode loginId churn) → same, but also update stored `loginId`. Else check monthly limit (raise `LIMIT_EXCEEDED:...` if exhausted), create `PENDING`, fetch, on success `CONNECTED` + `lastSyncAt` + `recordConnection` (counts quota), on failure `ERROR` + `errorMessage` (**failed connections do not count against limit**).
- **refresh**: status→`CONNECTED`, clear error, **no API call, no `lastSyncAt` write**.
- **resync**: owner check; `canConnect` gate (`LIMIT_EXCEEDED:...`); `force_refresh` (real fetch); `recordConnection`.
- **ConnectionLimit**: calendar-month key `yyyy-MM` from current date; default cap **5/month** (`SAVEVIA_CONNECTION_MAX_PER_MONTH`); `get` auto-creates the row; `record_connection` increments + `CONNECT` history; `record_disconnect`/`record_refresh` write history only. `canConnect`/`remaining` derive from the row.
- **demo data**: always one chequing account (debit txns → `cardUsedId` null = missed cashback) + 1–2 random credit-card accounts matched to `userCardIds`. Credit-card matching = bank-short-name gate + keyword score (≥3) + type hints (VISA/MASTERCARD/AMEX/CASHBACK/INFINITE). Transaction `amount` = `Debit` (positive) or `-Credit`. Randomness made **injectable** (a `Random`-like seam + uuid factory) so tests are deterministic; production uses real `random`/`uuid4`.
- **account type map**: CHEQUING/CHECKING→CHECKING, SAVINGS→SAVINGS, CREDIT/CREDITCARD→CREDIT_CARD, LOC/LINEOFCREDIT→LINE_OF_CREDIT, else OTHER. Mask = `****` + last 4.

### 4.5 Real Flinks REST path (inert)

`flinks/client.py` ports `authorizeWithFlinks` (POST `/{customerId}/BankingServices/Authorize`) and `getAccountsDetail` (POST `.../GetAccountsDetail`, `WithTransactions`, `DaysOfTransactions=Days90`, poll up to 10× with 3s sleep on async 202). Reached only when `FLINKS_SANDBOX=false` **and** loginId not `demo-`. Not exercised by tests beyond client-shape unit tests (no contract); documented as such.

## 5. Workstream B — AI per-recommendation explanations

Port `OpenAiService.generateExplanations` into a Python helper invoked from `modules/optimizer_api/service.py` (replacing the TODO at `service.py:141`):

- Per-`CategoryRecommendation`, locale-aware system message + single-category prompt with pre-computed conclusions; model `gpt-4o-mini`, temperature `0.8`; concurrent across categories (asyncio gather, bounded).
- On success fill `recommendation.ai_explanation`; preserve existing quota flow (`check_can_use_ai` → fill → `record_ai_usage`); on any failure swallow and leave explanation empty (current behavior). Gated by `enable_ai_explanation` + `user_id` + `OPENAI_ENABLED`/key present.
- Unit-tested with a mocked LLM (no spend); the real call is exercised only in the opt-in `live` regression (Workstream D) if desired.

## 7. Workstream D — real regression

### 7.1 Memory-quality (no Java needed)
- Expand `tests/modules/memory/fixtures/sample_conversations.json` from 10 → **20+** cases (DoD threshold).
- Run `pytest -m live tests/modules/memory/test_extraction_quality.py` against real OpenAI (`OPENAI_API_KEY` present). Assert ≥80% match vs expected; record the measured ratio in the PR/commit notes. Bounded spend (~20 short completions).

### 7.2 SSE structural (needs Java)
- Boot the Java stack from the built jar: `savevia-eureka` + `savevia-card` + `savevia-user` + `savevia-optimizer` (MySQL/Redis already up via Docker). Seed a known user + cards.
- Record N canonical chat conversations (the 10 prompts named in `tests/fixtures/sse_replay/README.md`) from Java `POST /api/v1/chat/stream`; normalize each to its **event-name sequence + tool-call set + done/error framing** (content deltas dropped — LLM output is non-deterministic).
- Populate `tests/fixtures/sse_replay/cases.json` + per-case expected files; flip the `@pytest.mark.skipif(not CASES)` in `test_sse_regression.py` to a real assert that the Python serializer reproduces the same event structure.
- **Honest fallback**: if the full Java stack cannot boot cleanly in this environment, record whatever subset is reachable, commit those fixtures, document the exact capture procedure, and report which cases are asserted vs pending — never fake a green.
